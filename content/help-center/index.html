Help Center

A portable documentation system with client-side search and auto-generated navigation.

Product Manager & Creator • 2026

The Product

TripDeck's help center, one of the production sites running on this system.

Help Center is a lightweight, self-contained documentation engine built using native Web Components. It provides portable internal infrastructure enabling web applications to add searchable support documentation via simple configuration.

While working on projects such as QR Maker, FileNamer, and Icon Studio, I observed a recurring need. Each web tool needs public documentation that offers client-side search, category browsing, heading-based navigation, and dark mode. Help Center merges these requirements into a single reusable foundation.

The original QR Maker support page was a single static HTML file with no search or scaffolding. FileNamer expanded on this by organizing articles into dedicated folders with client-side fuzzy search, but hardcoded project names directly into the components. When Icon Studio needed user documentation, the need for a repeatable solution became clear.

Help Center isolates all application branding, routing, navigation links, and metadata into a file called docs-config.json. This keeps the Web Component source code identical for each deployment.

An article in the FileNamer help center showing built-in headings, table of contents, and nav bar with search.

Key Features

  • Automated Navigation & Scroll Spy: Sidebar navigation and Table Of Contents are automatically generated from article heading tags with the active section highlighted during scroll.
  • System-Aware Theme Engine: Native dark, light, and system color preference matching with instant persistence.
  • Client-Side Fuzzy Search: Full-text search with word stemming across all articles without external API dependencies or heavy search indexes.
Help Center displaying search results for in-article content.
  • CLI Workflows & Indexing: Interactive CLI scripts automate article creation and compile the local search index.
  • Accessible Lightbox Modal: Built-in image overlay support for article screenshots, featuring keyboard navigation (Escape key dismiss) and backdrop focus trapping.
  • Configurable CTAs: Sidebar callout cards and navigation links configured in a single JSON file docs-config.json

My Role

As creator and sole developer, I defined the design, architecture, and ongoing maintenance of Help Center as a shared component library across my web application portfolio.

  • Discovery & Pattern Recognition: Identified recurring documentation requirements across multiple standalone web apps. Standardized client-side search, layout templates, and asset pipelines into a unified codebase.
  • Architecture & Portability: Abstracted app-specific identifiers, URLs, promotional links, and themes into a centralized configuration file, keeping component files 100% agnostic.
  • Component Engineering: Built native HTML5 Web Components for search indexing, responsive sidebars, theme toggling, and image lightboxes using zero external libraries or bundlers.
  • Upstream Iteration & Maintenance: Integrated Help Center into active projects like TripDeck and Icon Studio, feeding real-world usability fixes such as keyboard accessibility and dynamic sidebar CTAs back into the core template.

Deployments & Impact

Help Center powers support sites across several production web applications, including QR Maker, Icon Studio, FileNamer, and TripDeck, all featuring comprehensive guides, image lightboxes, and app CTAs.

Standardizing Help Center reduced the setup time for new product documentation. Spinning up a new help site now requires only running the setup script, defining docs-config.json, and writing user guides in vanilla HTML files. Custom front-end UI work for each new application has been eliminated.

Treating documentation infrastructure like a product it delivered a consistent, searchable support experience for end-users and an easy authoring workflow for every new product I work on, allowing me to focus on product, documentation, and features.
